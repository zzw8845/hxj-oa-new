同步前请先确认（4 件事）

  • 项目内配置已就位：工程根目录的 .apifox-helper.properties 负责把时间字段渲染成字符串。 没有它，前端会看到 {year,month,day…} 这种和真实响应不符的结构。
  • 只改注释、别在 Apifox 上手工补：插件当前是「覆盖所有字段」模式， 手工在 Apifox 上补的说明会在下次同步时被覆盖。要补说明 → 补到代码注释里。
  • 别配 method.return，也别给查询对象参数加 @ModelAttribute： 插件的内置规则是「无注解 = query 参数，@ModelAttribute = form-data 参数」， 本项目的 DocumentQuery / SealQuery / LedgerExportQuery 现在恰好正确识别为 query；加上注解反而变成 form-data。 method.return 则会让响应变成双层包装 R<R<T>>。
  • 同步范围按模块勾选：插件已绑定 oa-system / oa-flow / oa-document / oa-boot / oa-backend 五个模块， 全勾会重复同步；按需勾选即可。

同步后请逐项自查（这些只有真跑一遍插件才能确认）

  • 任意 R<PageResult<X>> 接口（如 GET /api/documents）：响应里应能看到 R 的 4 个字段， 且 data 里能看到 PageResult 的 5 个字段。 若 data 只显示成空对象 {}，说明泛型没被展开 —— 把配置里第 4 节注释掉的两行 json.rule.convert 放开后重新 Sync。
  • GET /api/documents：应展开出 DocumentQuery 的字段名作为 query 参数， 而不是一个名字叫 query 的单个参数。
  • 目录名：应与各控制器类注释的首行一致（如「部门管理」「待办与审批动作」）。
